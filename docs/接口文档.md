## 1. 统一约定

### 1.1 响应结构

所有 `/api/v1/**` 接口统一返回：

```json
{ "code": 0, "msg": "success", "data": { } }
```

列表接口的分页结构统一为：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "items": [ ],
    "total": 128,
    "page": 1,
    "page_size": 20
  }
}
```

参数校验失败（HTTP 422）会返回**字段级中文提示**，而不是裸露的 Pydantic 结构：

```json
{
  "code": 4220,
  "msg": "参数校验失败 → qty_good: 确保该值大于或等于 0；operation_id: 字段必填",
  "data": { "errors": [
    { "field": "qty_good", "message": "确保该值大于或等于 0" },
    { "field": "operation_id", "message": "字段必填" }
  ] }
}
```

### 1.2 鉴权

除 `/api/health`、`POST /api/v1/auth/login`、`GET /api/v1/orders/status-machine`、
`GET /api/v1/quality/spc/rules` 外，其余接口均需携带 JWT：

```
Authorization: Bearer <access_token>
```

令牌有效期默认 720 分钟。

### 1.3 幂等

所有**写接口**均可携带 `Idempotency-Key` 请求头（也可放在报工请求体的
`idempotency_key` 字段）。同一 Key 重复提交时：

* 首次请求 → 正常执行，并把响应快照写入 `sys_idempotency`；
* 重复请求 → 直接回放首次结果，**不会**产生第二笔业务数据；
* 并发请求 → 后到者命中 `IN_PROGRESS` 状态并返回 409，提示"操作正在处理中"。

### 1.4 错误码

| code | HTTP | 含义 | 典型场景 |
| --- | --- | --- | --- |
| `0` | 200 | 成功 | — |
| `4000` | 400 | 业务规则不满足 | 报工数量超过计划剩余量 |
| `4003` | 401 / 403 | 未登录 / 无接口权限 | 操作工调用工单下达接口 |
| `4004` | 404 | 数据不存在 | 工单 ID 不存在 |
| `4009` | 409 | 状态冲突 / 幂等冲突 | 非法状态流转、重复报工、库存不足 |
| `4220` | 422 | 参数校验失败 | 字段缺失或越界 |
| `5000` | 500 | 服务内部错误 | 未捕获异常 |

## 3. 生产工单 `/api/v1/orders`

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/orders` | `order:view` | 工单列表（分页 + 状态/产品筛选） |
| POST | `/orders` | `order:create` | 创建工单（草稿态） |
| GET | `/orders/status-machine` | 公开 | 状态机定义（前端动态渲染按钮） |
| GET | `/orders/{order_id}` | `order:view` | 工单详情（工序、物料需求、报工流水） |
| POST | `/orders/{order_id}/transition` | `order:release/start/complete/cancel` | 状态流转 |
| POST | `/orders/{order_id}/report` | `order:report` | 工序报工 |
| GET | `/orders/{order_id}/allowed-transitions` | `order:view` | 当前状态下可流转的目标状态 |

### 3.1 状态机

```
DRAFT ──下达──> RELEASED ──开工──> IN_PROGRESS ──完工──> COMPLETED
  │                │                   │
  │                └────取消───────────┤
  └────────────────取消────────────────┴──> CANCELLED

IN_PROGRESS ──暂停──> PAUSED ──恢复──> IN_PROGRESS
```

流转表是**唯一真源**（`backend/app/models/order.py::WORK_ORDER_TRANSITIONS`），
前端按钮由 `GET /orders/{order_id}/allowed-transitions` 驱动，与后端判定同源，
因此不存在"前端能点、后端拒绝"的错位。

### 3.2 创建工单

```bash
curl -X POST http://localhost:8000/api/v1/orders \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"product_id":1,"routing_id":1,"qty_planned":500,"priority":3,"owner_group":"甲班"}'
```

### 3.3 报工（幂等演示）

```bash
curl -X POST http://localhost:8000/api/v1/orders/1/report \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: report-wo1-op1-20260301-001' \
  -d '{
        "operation_id": 1,
        "qty_good": 100,
        "qty_defect": 2,
        "employee_id": 1,
        "shift_id": 1,
        "measurements": [10.02, 10.01, 9.99, 10.03, 10.00]
      }'
```

用**完全相同的 `Idempotency-Key`** 再发一次，第二次返回：

```json
{ "code": 0, "msg": "success（幂等命中，已回放首次结果）", "data": { "replayed": true, "report_id": 12 } }
```

报工一次事务内完成的动作（全部成功或全部回滚）：

1. 校验工单状态与工序状态；
2. 校验累计报工量不超过计划量（超出返回 `4009`）；
3. 写入报工流水（唯一约束 `uk_pp_report_idempotency` 兜底）；
4. 按 BOM 扣减物料库存（不足则整笔回滚，返回 `4009`）；
5. 若携带 `measurements`，写入 SPC 子组并执行判异；
6. 命中判异 → 自动生成待处理质检单；
7. 末工序报满 → 工单自动流转到 `COMPLETED`。

### 4.1 录入子组

```bash

  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{
        "product_id": 1, "operation_code": "OP20",

        "feature_name": "内孔直径",
        "nominal": 10.0, "upper_spec": 10.05, "lower_spec": 9.95
      }'
```

### 4.2 控制图数据结构

`GET /quality/spc/chart/1/OP20` 返回内容可直接喂给 ECharts：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "subgroups": [{ "seq": 1, "xbar": 10.01, "range": 0.04, "n": 5, "recorded_at": "2026-03-01T08:10:00" }],
    "xbar_chart": { "cl": 10.0038, "ucl": 40.0225, "lcl": 9.9851 },
    "range_chart": { "cl": 0.0312, "ucl": 0.0660, "lcl": 0 },
    "sigma_hat": 0.0134,
    "capability": { "cp": 1.24, "cpk": 1.18 },
    "violations": [{ "seq": 12, "rule": 1, "desc": "1 点超出控制限", "points": [12] }]
  }
}
```

计算口径（`backend/app/services/spc_core.py`，纯函数、零依赖、可单测）：

* X̄ 图：`UCL/LCL = X̄̄ ± A₂·R̄`
* R 图：`UCL = D₄·R̄`、`LCL = D₃·R̄`
* 过程能力：`σ̂ = R̄/d₂`，`Cp = (USL-LSL)/6σ̂`，`Cpk = min((USL-X̄̄), (X̄̄-LSL))/3σ̂`
* 系数 A₂/D₃/D₄/d₂ 按子组容量 n 查表（n = 2~10）

### 4.3 判异准则（GB/T 4091 全 8 条）

| 编号 | 准则 |
| --- | --- |
| 1 | 1 点超出控制限（±3σ 之外） |
| 2 | 连续 9 点落在中心线同一侧 |
| 3 | 连续 6 点递增或递减 |
| 4 | 连续 14 点交替上下 |
| 5 | 连续 3 点中有 2 点落在 ±2σ 之外 |
| 6 | 连续 5 点中有 4 点落在 ±1σ 之外 |
| 7 | 连续 15 点落在 ±1σ 之内 |
| 8 | 连续 8 点落在 ±1σ 之外且两侧均有 |

默认启用 `1,2,3,5,6`（`SPC_RULE_SET` 可配置）。

### 5.1 SSE 订阅

```
GET /api/v1/dashboard/stream
Accept: text/event-stream
Authorization: Bearer <token>   # 也可以用 ?token=<jwt> 便于 EventSource 直连
```

服务端每 `SSE_PUSH_INTERVAL_SEC`（默认 2 秒）推送一帧，每 15 秒发送心跳注释：

```
event: device
data: {"devices":[{"equipment_code":"EQ-001","status":"RUNNING","oee":0.82}],"ts":1772000000}

: heartbeat
```

链路：**数采网关 tick（3s）→ Redis 写入设备快照 + 发布事件 → SSE Hub 广播 → 前端 ECharts 秒级刷新**。
Redis 不可用时自动降级为进程内内存 pub/sub，链路与语义完全一致。

## 10. 典型调用序列

```
1. POST /auth/login                       → 取 token
2. GET  /master                           → 取产品 / 工艺路线 / 物料
3. POST /orders                           → 建工单（DRAFT）
4. POST /orders/{id}/transition RELEASED  → 下达
5. POST /orders/{id}/transition IN_PROGRESS → 开工
6. POST /inventory/issue                  → 发料
7. POST /orders/{id}/report               → 报工（带 Idempotency-Key）
8. POST /quality/spc/subgroups            → 录入样本 / 自动判异
9. GET  /quality/tasks                    → 处理自动生成的质检单
10. GET /reports/{code}                   → 出报表
```
