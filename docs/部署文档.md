# 部署文档

本项目提供**三种部署形态**，从零依赖演示到生产级编排全覆盖。

| 形态 | 依赖 | 适用场景 | 启动命令 |
| --- | --- | --- | --- |
| A. 本地直跑 | Python 3.10+ | 开发调试、单机构建演示 | `bash scripts/start.sh` |
| B. Compose 轻量版 | Docker | 没有 MySQL/Redis 也要一键起 | `bash scripts/docker-up.sh lite` |
| C. Compose 完整版 | Docker | 与简历技术栈完全一致 | `bash scripts/docker-up.sh` |

---

## A. 本地直跑（SQLite 兜底）

```bash
# 1. 安装依赖（自动创建 .venv）
bash scripts/start.sh          # Windows: scripts\start.bat

# 2. 另开一个终端写入示例数据
bash scripts/seed.sh           # Windows: scripts\seed.bat

# 3. 打开
#    前端     http://localhost:8000/
#    Swagger  http://localhost:8000/docs
```

要点：

* 默认 `DB_ENGINE=sqlite`，数据落在 `data/mes.db`，**不需要安装 MySQL**；
* Redis 连不上时自动降级为进程内内存缓存（见 `app/realtime/redis_client.py`），
  设备实时状态、SSE 推送、幂等缓存全部照常工作；
* 复制 `.env.example` 为 `.env` 可覆盖任意配置（如切到 MySQL）。

切到 MySQL：

```bash
export DB_ENGINE=mysql
export MYSQL_HOST=127.0.0.1 MYSQL_PORT=3306
export MYSQL_USER=root MYSQL_PASSWORD=mes123456 MYSQL_DB=mes
```

后端启动时会自动 `CREATE TABLE`（31 张表），无需手工执行建表脚本。

## B. Docker Compose 轻量版（单容器 + SQLite）

```bash
bash scripts/docker-up.sh lite       # Windows: scripts\docker-up.bat lite
```

等价于：

```bash
docker compose -f docker-compose.lite.yml up -d --build
docker compose -f docker-compose.lite.yml exec api python -m scripts.seed
```

* 只起 1 个容器 `mes-api-lite`，监听 `8000`；
* 数据落在卷 `api_data`（容器内 `/app/data/mes.db`）；
* `REDIS_ENABLED=false` → 内存缓存；
* 前端使用镜像内已构建的 `frontend/dist`。

## C. Docker Compose 完整版（MySQL 8 + Redis 7 + API）

```bash
bash scripts/docker-up.sh            # Windows: scripts\docker-up.bat
```

编排内容（`docker-compose.yml`）：

| 服务 | 镜像 | 端口 | 说明 |
| --- | --- | --- | --- |
| `db` | `mysql:8.0` | 3306 | `utf8mb4` / `+08:00`，带 healthcheck |
| `cache` | `redis:7-alpine` | 6379 | AOF 持久化，带 healthcheck |
| `api` | 本地多阶段构建 | 8000 | FastAPI + 已构建的 Vue3 前端 |
| `seeder` | 本地多阶段构建 | — | 一次性写入示例数据，执行完退出 |
| `web` | `nginx:1.27-alpine`（profile `nginx`） | 80 | 可选反向代理 |

启动顺序由 `depends_on: condition: service_healthy` 保证：
**MySQL 就绪 → Redis 就绪 → API 启动 → seeder 写数据**。

镜像构建分两阶段（`backend/Dockerfile`）：

1. `node:22-alpine`：`npm ci && npm run build` → `frontend/dist`
2. `python:3.12-slim`：`pip install -r requirements.txt` + 拷贝后端源码与前端产物

最终镜像自带前端，访问 `http://localhost:8000/` 即可，无需额外 Nginx。

### 常用运维命令

```bash
docker compose ps                    # 服务状态
docker compose logs -f api           # 跟踪日志
docker compose logs -f seeder        # 查看播种结果
docker compose exec api python -m scripts.seed --reset   # 重置示例数据
docker compose down                  # 停止（保留数据卷）
docker compose down -v               # 停止并清空数据
docker compose --profile nginx up -d # 额外启用 Nginx 反向代理
```

### 可选：Nginx 反向代理

```bash
docker compose --profile nginx up -d
# 访问 http://localhost/
```

`deploy/nginx.conf` 对 SSE 路径 `/api/v1/dashboard/stream` 单独关闭了
`proxy_buffering`，否则看板无法做到秒级刷新。

## D. 环境变量

完整清单见 `.env.example`，关键项：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DB_ENGINE` | `sqlite` | `sqlite` / `mysql` |
| `MYSQL_*` | — | MySQL 连接参数 |
| `SQLITE_PATH` | `data/mes.db` | SQLite 文件路径 |
| `REDIS_ENABLED` | `true` | `false` 时直接用内存缓存 |
| `REDIS_HOST/PORT` | `localhost:6379` | Redis 地址 |
| `SECRET_KEY` | 内置 | **生产必须修改** |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | `720` | JWT 有效期 |
| `GATEWAY_ENABLED` | `true` | 设备数采网关开关 |
| `GATEWAY_INTERVAL_SEC` | `3` | 设备上报周期 |
| `SSE_PUSH_INTERVAL_SEC` | `2` | 看板推送周期（秒级刷新） |
| `SPC_RULE_SET` | `1,2,3,5,6` | 启用的判异准则 |
| `FRONTEND_PREFER` | `dist` | `dist`（Vite 产物）/ `standalone`（免构建版） |

## E. 验证清单

部署完成后逐项自检：

```bash
# 1. 健康检查
curl http://localhost:8000/api/health

# 2. 登录取 token
TOKEN=$(curl -s -X POST http://localhost:8000/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"mes@2026"}' | python -c "import sys,json;print(json.load(sys.stdin)['data']['access_token'])")

# 3. 看板
curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/dashboard | head -c 300

# 4. 报表（8 张全部应有数据）
for c in work_order_progress yield_rate equipment_oee output_daily \
         operation_efficiency defect_pareto inventory_turnover worker_performance; do
  echo -n "$c -> "; curl -s -H "Authorization: Bearer $TOKEN" \
    "http://localhost:8000/api/v1/reports/$c" | head -c 60; echo
done

# 5. SPC 控制图
curl -H "Authorization: Bearer $TOKEN" http://localhost:8000/api/v1/quality/spc/chart/1/OP20 | head -c 300

# 6. SSE（应持续输出 device 事件帧）
curl -N "http://localhost:8000/api/v1/dashboard/stream?token=$TOKEN"
```

## F. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面 404 | 前端产物未构建 | `cd frontend && npm install && npm run build`，或设 `FRONTEND_PREFER=standalone` |
| `/api/health` 中 `cache_backend=memory` | Redis 不可达 | 属正常降级，功能不受影响；需要真实 Redis 时检查 `REDIS_HOST` |
| 报工返回 4009 | 超过计划量或库存不足 | 业务校验生效，属预期行为 |
| MySQL 启动后 API 连不上 | MySQL 初始化未完成 | `docker compose ps` 确认 `db` 为 healthy 后再访问 |
| 镜像构建慢 | npm/pip 走境外源 | Dockerfile 已内置 npmmirror 与 tuna 镜像源 |
